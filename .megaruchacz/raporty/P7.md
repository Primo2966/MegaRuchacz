# P7 - udzial MegaRuchacza w otwarciu sesji + nowy wyglad okna nadzorcy (2026-09-25)

## A. Otwarcie sesji - pomiar

Zmierzone na tej maszynie 2026-09-25 ok. 15:00, `narzedzia\koszt-pamieci.ps1 -Start`.

| co | liczba | skad |
|---|---:|---|
| **cale otwarcie sesji** | **~186 968 tok.** (mediana) | 10 ostatnich sesji Claude Code z 14 dni, z 8 projektow; min 63 061, max 204 781 |
| z tego MegaRuchacz | ~6 406 tok. = **3%** | rachunek koszt-pamieci: 6 291 start (globalny CLAUDE.md) + 115 przypomnienia doklejonego do 1. wiadomosci |
| z tego sam Claude Code | ~180 562 tok. = 97% | reszta: instrukcje, opisy narzedzi (w tym MCP), lista skilli |
| **start jednego workera** | **~32 104 tok.** (mediana) | 20 ostatnich workerow w rolach implementer/scout/verifier/zastepca (min ~20 900, max ~38 800) |
| z tego MegaRuchacz w workerze | ~6 291 tok. = ~20% | globalny CLAUDE.md trafia tez do podagenta (sprawdzone: zalacznik `instructions` w jego transkrypcie) |

**Metoda.** Transkrypty: `~\.claude\projects\<projekt>\*.jsonl` (sesje) i `...\<sesja>\subagents\agent-*.jsonl`
z `agent-*.meta.json` (pole `agentType`). Z kazdego pliku czytany tylko poczatek, do pierwszej odpowiedzi
modelu: `input_tokens + cache_creation_input_tokens + cache_read_input_tokens` z `message.usage` = caly
kontekst przy tej odpowiedzi. Od tego odjeta ostatnia wiadomosc uzytkownika przed nia (znaki / 3 - szacunek;
dla workera to tresc zlecenia). Mediana z ostatnich N plikow (wg daty zapisu), tylko z 14 dni, bo zestaw
narzedzi sie zmienia. Odpowiedzi `<synthetic>` / zerowe pomijane. Czas pomiaru ~1 s.

**Sprawdzenie sensu - wynik NIE jest w spodziewanym rzedzie 20-40 tys.** Od ok. 14.09 kazda sesja
startuje z ~180-200 tys. tokenow (wczesniej ~45-70 tys.). To nie blad pomiaru:
- rozklad jest dwugarbny i zbiega sie w czasie: sesje z 10-11.09 ~63-70 tys., wszystkie od 14.09 ~180-208 tys.;
- ten sam model, te same pliki CLAUDE.md, a podagenci ze WSZYSTKIMI narzedziami (general-purpose) startuja
  z ~150-180 tys., podczas gdy workerzy z waskim zestawem narzedzi (implementer/scout) z ~27-40 tys. -
  roznice ~130-150 tys. robia wiec opisy narzedzi (w tej maszynie podlaczone sa m.in. higgsfield, Chrome,
  Claude Docs, Google Drive, context7, lore - dokladnej liczby narzedzi ani ich wagi nie mierzylem);
- tresc tekstowa, ktora transkrypt zapisuje (instrukcje CLAUDE.md, lista skilli, lista agentow, instrukcje MCP,
  prompt systemowy), to ok. 90 tys. znakow ~ 30 tys. tokenow - reszta nie jest tekstem w transkrypcie,
  czyli pasuje do schematow narzedzi, ktorych transkrypt nie zapisuje.
Wniosek dla uzytkownika: MegaRuchacz to ~3% otwarcia sesji; ~97% to Claude Code z podlaczonymi serwerami MCP.
Rozbicia "Claude Code sam" na instrukcje / narzedzia / MCP z transkryptu zrobic sie nie da (narzedzia nie
sa w nim zapisywane) - to NIEZMIERZONE, okno mowi tylko "Claude Code sam".

**Braki pomiaru nie sa zerem.** Brak katalogu transkryptow, brak jakiejkolwiek sesji z odpowiedzia
modelu w 14 dniach, nieczytelny JSON, wywrotka pomiaru - kazde daje `Powod`, a okno pisze
"nie zmierzono, bo ..." bez paska i bez procentu (zrzut `P7-negatywna-przeglad.png`, podstawiony pusty
katalog domowy). Brak workerow w oknie: "Start jednego workera: nie zmierzono, bo ...".

## B. Wyglad okna

Zasady ze skilla `impeccable` (tryb Operate) przeniesione na WinForms: jedna rodzina kroju (Segoe UI),
hierarchia wielkoscia i waga zamiast koloru, kolor tylko tam, gdzie niesie znaczenie (czerwony/zolty/zielony
jak dotad + jeden spokojny niebieski dla czesci MegaRuchacza na pasku), liczby wyrownane do prawej,
wiecej powietrza (karty 22 px wciecia, 14 px odstepu), jezyk bez zargonu, braki widoczne slowami.

- **Szerokosc** liczona z `Screen.PrimaryScreen.WorkingArea`: do 1240 px wnetrza (tu 2560x1392 -> 1256 x 1352
  z ramka; bylo 866), nigdy wiecej niz obszar roboczy - 80 px, nigdy mniej niz 900. Wysokosc jak dotad
  z tresci przegladu, min. 760 (zeby szczegoly i warstwy mialy miejsce), max ekran - 40.
- **Przeglad**: nowa karta "Otwarcie sesji" zaraz pod alarmami (duza liczba, pasek MegaRuchacz/Claude Code,
  dwa wiersze legendy z liczbami i procentem, zdanie "co to znaczy dla portfela", podstawa pomiaru i start
  workera). Karty kosztow podpisane "MegaRuchacz dokleja/doklada...", zeby nie mylily sie z calym otwarciem.
  Wykres szerszy, podpisy dat w jednej linii, legenda panelami zamiast znaku "■".
- **Szczegoly**: zamiast jednego TextBoxa 8 kart sekcji, najwazniejsze na gorze: Co wymaga uwagi (pelna
  tresc) -> Otwarcie sesji (skad liczba, tabela sesji i workerow) -> Rachunek pozycja po pozycji (tabela
  z paskami udzialu; linie, ktore nie pasuja do wzorca, ida jako tekst - nic nie ginie) -> Nauka z rozmow ->
  Koszt nauki dzien po dniu (tabela) -> Zmiany w pamieci -> Wersja -> Nadzorca i gdzie co lezy. Etykiety po
  polsku z ogonkami ("Nowsza na serwerze" zamiast "na gicie"). Wszystko, co bylo dotad, zostalo (sprawdzone
  porownaniem wydruku -Raport).
- **Warstwy pamieci**: lista szersza (48%), wyzsze wiersze (ImageList 1x26), nazwy z ogonkami; podglad
  z dwiema kolumnami (Wczytuje sie / Stan / Rozmiar / Trwalosc / Zmieniony / Kto pisze / Co to jest /
  Sciezka) nad trescia.
- Wydruk `-Raport` / `-Raz` sklada sie z tych samych sekcji (jedna struktura `Sekcje-Szczegolow`), ma sekcje
  OTWARCIE SESJI. Przyciski, alarmy, dymki, zegar, zamek, `-Proba` - bez zmian w zachowaniu.

Pomiar liczy sie przy otwarciu okna i przy "Przelicz liczby teraz" - nie w dozorze co 15 min
(nikt go wtedy nie oglada; zapobiega doklejaniu procesu do kazdego przebiegu).
